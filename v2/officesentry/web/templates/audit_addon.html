Create the app by hand instead

If your Conditional Access blocks device sign-in:

  1. Generate the add-on's certificate below, then download its .cer file from App connection.
  2. In the Entra admin centre: App registrations → New registration, named “{{ default_name }}”. Supported account types: Accounts in any organizational directory.
  3. Redirect URI (Web): {{ redirect_uri }}.
  4. Under Certificates & secrets, upload the .cer file. Under API permissions → Add a permission → Office 365 Management APIs → Application permissions, tick ActivityFeed.Read and nothing else.
  5. Copy the app's Application (client) ID into its card on App connection. Saving it switches the add-on on.

What the add-on reads and sends

One application permission, ActivityFeed.Read on the Office 365 Management APIs. From each client that approves it, the reports show:

    {% for line in client_words %}
  • {{ line }}
    • {% endfor %}

It never reads:

    {% for line in never %}
  • {{ line }}
    • {% endfor %}

Every request it makes reads, except two that Microsoft's feed needs: start asks Microsoft to make a client's new audit records available to the add-on's app, and stop asks it to stop. Office Sentry sends start once per kind of record ({{ content_types|join(' and ') }}), after it has confirmed that a client you asked for approved the add-on; and stop the same way when you switch the add-on off for a client or delete the client. Neither changes anything in the client's tenant, and a nightly collection never sends either.
