Let your team sign in with Microsoft

{% if active %}Waiting for sign-in{% endif %}

Your staff sign in with the Microsoft account they already use, protected by your own Conditional Access and MFA. Office Sentry creates one small app in your tenant for it; your read-only connection to client tenants doesn't change.

  1. Sign in to Microsoft
    {% if active %} {{ device_code(sign_in, url_for('sso.check_setup'), url_for('sso.cancel_setup'), seconds_left, "Sign in as a Global Administrator of your own (the MSP's) tenant, or someone who can create app registrations and assign people to them. Microsoft may ask you to let Microsoft Graph Command Line Tools (Microsoft's own app) manage apps for you. Office Sentry uses this sign-in once and doesn't keep it.") }} {% else %} {% if status == 'failed' %}
    {{ icon('alert') }}
    The sign-in app wasn't created. {{ sign_in.error }}
    {% endif %} Office Sentry shows you a code; you sign in on Microsoft's page in another tab, as a Global Administrator of your own tenant. Your password never passes through Office Sentry.
    {{ csrf() }}
    More options
    {% endif %}
  2. Office Sentry creates the sign-in app
    A single-tenant app named “{{ sign_in.name if sign_in else default_app_name }}” with no permissions at all: it only tells Office Sentry who signed in. It gets a certificate whose private key never leaves Office Sentry, an app role for each Office Sentry role (Admin for Administrator, Analyst for Second line, and so on), and you're assigned Admin. Only people you assign can sign in.
  3. Try it
    Microsoft sign-in is turned on straight away. Connect your own account from the button that appears here, then sign out and press Sign in with Microsoft. Passwords keep working until you turn them off.
Set it up by hand instead

If Conditional Access blocks device sign-in, or you'd rather make the app yourself:

  1. Make the certificate here and download its .cer file.
  2. In the Entra admin centre: App registrations → New registration. Name it {{ default_app_name }}. Supported account types: Accounts in this organizational directory only. Redirect URI (Web): {{ redirect_uri }}.
  3. Under Certificates & secrets → Certificates, upload the .cer file.
  4. Under App roles, create a role for each Office Sentry role you'll use, all for Users/Groups, with these values: {% for value, name in app_roles %}{{ value }} ({{ name }}){{ ', ' if not loop.last else '' }}{% endfor %}. Admin is the one you need now.
  5. Under Enterprise applications → {{ default_app_name }} → Properties, set Assignment required to Yes. Under Users and groups, assign yourself the Admin role.
  6. Copy the app's Application (client) ID and Directory (tenant) ID from its overview page into the form below.

Replacing the certificate

Sign-ins keep using the current certificate until you switch, so nothing stops in between.

  1. New certificate made
    {{ s.sso_next_thumbprint }}, valid until {{ s.sso_next_not_after|day }}.
  2. Add it to the app registration, next to the old one
    In the Entra admin centre: App registrations → {{ s.sso_app_name or default_app_name }} → Certificates & secrets → Certificates → Upload certificate, and choose the new .cer.
    {{ icon('download') }} Download new .cer
  3. Switch to it
    Sign-ins use the new certificate from then on. A newly uploaded certificate can take 5 to 10 minutes to work. Afterwards, delete the old one from the app registration.
