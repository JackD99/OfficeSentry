Setting up the Microsoft 365 option

This uses a small separate app in your own tenant that can only send mail. Client tenants are never asked for mail permissions.

  1. Open entra.microsoft.com signed in to your own tenant, then go to App registrations → New registration. Name it “Office Sentry mail”, keep “Single tenant”, and select Register.
  2. Copy the Application (client) ID and Directory (tenant) ID into the boxes on the left.
  3. Go to API permissions → Add a permission → Microsoft Graph → Application permissions, tick Mail.Send, select Add, then Grant admin consent.
  4. Make the certificate on the left and select Download .cer. In the app go to Certificates & secrets → Certificates → Upload certificate and choose that file. (Using a client secret instead: Client secrets → New client secret, and copy the Value, not the ID.)
  5. Limit the app to the one mailbox. Mail.Send on its own lets the app send as anyone in your tenant. In Exchange Online PowerShell (Connect-ExchangeOnline) run: 
    New-ApplicationAccessPolicy -AppId {{ app_id }} -PolicyScopeGroupId {{ mailbox }} -AccessRight RestrictAccess -Description "Office Sentry mail"
    Check it with a different mailbox, which should say Denied: 
    Test-ApplicationAccessPolicy -Identity someone.else@{{ mailbox.split('@')[-1] }} -AppId {{ app_id }}
    Then tick I've limited the mail app to this one mailbox on the left and save. It can take up to an hour to apply.
    Using RBAC for Applications instead

    Exchange's newer way does the same: assign the app the Application Mail.Send role with a management scope that only covers {{ mailbox }}. If you do, also remove Mail.Send from the app's API permissions in Entra, or the app can still send as anyone.

  6. Save, then send yourself a test.
